Project Vision
 We want to make a small web game called ShadowSnap, based on Legos. Players swap between a “shadow” screen and a “build” screen. In the shadow screen, the player rotates a completed build, which is hidden from view, around on a turntable and studies the shadow projected by the hidden Lego sculpture. In the build screen they have the loose bricks and try to rebuild that sculpture on a baseplate, which they can turn also. When their build throws the same shadow, the level ends with a quick animation and the next level unlocks.
Core Gameplay
1. Look – Rotate the build, and look at the shadow it projects on the wall

2. Guess and Build – Drag bricks from an inventory, rotate them, and snap them to a grid.

3. Test – Flip back; the game swaps in the player’s model. If the shadows line up, you win. If not, repeat.

Required Features
   * Two viewports that the player can switch with the Tab key.

   * Turntable that the player can rotate either by clicking and dragging, or possibly by just using a slider

   * A small set of brick types (2×2, 2×4, slope, etc.) that can be dragged, rotated, and snapped.

   * A win checker that compares the player’s bricks to the answer with a tiny tolerance.

   * Level progression is stored in localStorage so unlocked levels stay unlocked.

Stretch Goals

      * A “share level” button that copies a JSON code to the clipboard.

      * Softer shadows and a glow effect when you win.

Anticipated Challenges
            * Shadow quality vs. speed: High‑res shadows look good but hurt FPS. We can drop shadow detail while dragging bricks and raise it when the mouse is released. Or just render out 4-5 angles for user hints.

            * Brick snapping: We need bricks to lock on exact studs. We’ll round every move to standard steps and only allow 90° rotations.

            * Scope creep: Sandbox and sharing sound fun but are optional. We’ll only start them after the main game is fully working.
